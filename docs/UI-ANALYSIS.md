# UI 전수 분석서 (원본 SCORCH.DOC 기준 → 현대 웹 UI)

작성: 문기획 / 근거: SCORCH.DOC v1.5 / 원칙: 설명 문구 최소화, 오류·거절은 토스트
표기: **유지**=원본 그대로, **현대화**=주변 UI 교체, **삭제**=웹에서 불필요, [제안]=DOC 근거 없는 신규 설계, **미상**=EXE 확인 필요
화면 안 이름·문구는 SPEC 8절 용어집(음역 중심)을 따른다.

## U0. 원칙 요약
| 구분 | 내용 |
|---|---|
| 유지 | 게임 캔버스의 픽셀 해상도 느낌, 256색 팔레트, 폭발·핵폭발·궤적 연출, 하늘 7종, 지형 렌더링, 탱크 아이콘, 벽 색상, 연출 타이밍, 효과음 구성, 조작감과 수치(엔진 동일) |
| 현대화 | 로비, 방 목록, 대기실, 옵션, 상점, 인벤토리, HUD, 제어판, 확인창, 결과 화면, 폰트, 레이아웃 |
| 입력 | 키보드는 원본 키 유지 + 마우스·터치 병행 |
| 문구 | 설명 최소화(꼭 필요한 한 줄), 오류·거절 사유는 토스트(인라인 오류 박스 금지) |
| 계층 | 원본의 "화면 중앙 팝업 위에 겹치는 대화상자" → 모달/시트/드로어 3종으로 통일 |

공통 컴포넌트(대체안에서 반복 사용):
| 컴포넌트 | 용도 |
|---|---|
| 스텝퍼+슬라이더 | 원본의 Counter(숫자 증감) |
| 스위치 | 원본의 Toggle(체크박스) |
| 세그먼트/드롭다운 | 원본의 Cycle(선택지 순환) |
| 텍스트 필드 | 원본의 Text entry |
| 버튼 | 원본의 Button |
| 모달/바텀 시트/사이드 드로어 | 원본의 중앙 팝업 패널 |
| 토스트 | 오류·거절·시스템 알림 |
| 툴팁/설명 아이콘 | 원본의 긴 설명 문구(필요 시 한 줄로 축약해 노출) |

| 10 | Cycle(선택지 순환) | 클릭마다 다음 값, Alt+키는 이전 값 | 현재·전체 선택지가 안 보임 | 세그먼트 컨트롤 또는 드롭다운 |
| 11 | Toggle(체크박스) | 체크 표시 | 작은 클릭 영역 | 스위치(44px 터치 타깃) |
| 12 | Text entry | 캐럿 + ENTER/ESC | 취소·확정 방식이 불명확 | 텍스트 필드 + 확인/취소 |
| 13 | 사운드 메뉴: 효과음, 비행음(높이/속도/끔) | Cycle | 소리 미리 들을 수 없음 | 스위치 + 세그먼트, "들어보기" 버튼 [제안]. 개인 설정이라 방 설정이 아닌 설정 드로어에 둔다 |
| 14 | 하드웨어 메뉴(그래픽 모드, BIOS 키보드, 메모리, 포인터, 마우스 속도, 발사/낙하 지연) | Cycle/Counter | DOS 하드웨어 종속 | **삭제**. 발사·낙하 지연은 서버 고정(A2). 마우스 속도는 브라우저 기본 |

| 16 | 물리 메뉴(점성, 중력, 흙 공중 부유, 탱크 낙하, 경계 확장, 벽 효과) | Counter/Cycle | 값의 효과를 알기 어려움 | "물리" 탭. 슬라이더+현재값 표시, 벽 효과는 색 칩 6개 + 선택 |

## U3. 모바일/터치 조작 설계
원칙: 엔진 값은 원본과 같은 정수 단위·범위(파워 0~최대, 각도 0~90)를 쓰고, 터치는 입력 수단만 바꾼다. **키 반복 속도(증감 속도)는 미상이므로 터치 길게 누르기 반복도 EXE 확인 값에 맞춘다.**

| 조작 | 설계 [제안] |
|---|---|
| 각도·파워 | 하단에 슬라이더 2개(각도, 파워) + 양끝 −/+ 버튼. 길게 누르면 원본 키 반복과 같은 속도로 연속 증감. Shift·Alt 대응은 "정밀 모드" 토글(1단위 증감) |
| 드래그 조준 | 캔버스에서 내 탱크를 길게 눌러 끌면 방향=각도, 길이=파워로 변환(고무줄 방식). 놓으면 값만 설정(발사 아님). 각도 0~90 범위와 방향 규칙은 EXE 확인 후 적용 |
| 무기 선택 | 바텀 시트(그리드): 소유한 무기 카드(아이콘, 이름, 개수). 탭하면 선택하고 닫힘. 좌우 스와이프로 이전/다음 무기(TAB 대응) |
| 발사 | 화면 하단 우측 큰 원형 버튼. 탭 1회 발사. 오발 방지 옵션(길게 누르기/한 번 더 확인)은 설정에서 선택 [제안] |
| 장비·제어판 | 바텀 시트 탭 2개(장비 퀵바, 탱크 제어판). 배터리, 낙하산, 실드, 트리거, 유도, 연료 이동 |
| 이동(연료) | 이동 모드에서 좌/우 큰 버튼 길게 누르기 |
| 유도 표적 | 탱크 번호 배지를 탭하거나 지형 임의 지점을 탭 |
| 후퇴 | ☰ 메뉴 안(오입력 방지) + 확인 모달 |
| 핀치/스크롤 | 캔버스 확대·이동은 지원하지 않는다(원본 시점 고정). 브라우저 줌과 충돌 방지 [제안] |
| 세로/가로 | 세로: 캔버스 위·조작 아래. 가로: 캔버스 중앙, 조작 좌우 분할 |
| 터치 타깃 | 최소 44×44 CSS px |
| 다중 터치 | 동시 모드에서 터치 두 손가락 입력 허용(각도 슬라이더와 파워 슬라이더 동시) |

## U5. 입력 일관성 규칙
- 마우스 우클릭을 필수 입력으로 쓰지 않는다(원본 좌/우클릭 증감은 스텝퍼로 대체). 컨텍스트 메뉴는 가로채지 않는다.
- 양쪽 버튼 동시 클릭 발사는 삭제하고 발사 버튼으로 대체한다.
- 모든 조작은 키보드·마우스·터치 중 하나로 가능해야 한다.
- 오류·거절 사유는 토스트로 표시한다(예: 자금 부족, 보유 한도, 시작 불가 사유).
- 설명 문구는 최소화한다. 길어질 때는 툴팁/info 아이콘으로 한 줄만 노출한다.

## U6. 접근성·반응형·시각 설계

### U6.1 접근성
| 항목 | 설계 [제안] |
|---|---|
| 키보드 | 모든 주변 UI는 탭 이동과 포커스 링을 지원. 게임 화면의 키는 U4 |
| 스크린리더 | 라이브 영역에 턴 변경, 발사, 피해, 시간 초과, 방장 변경을 읽어 준다. 아이콘 버튼에 레이블 |
| 색 | 플레이어 색에 의존하지 않고 번호/모양을 병기. 색약 대응 팔레트 보조 표시(주변 UI) |
| 대비 | 주변 UI 텍스트 WCAG AA 이상 |
| 모션 | 시스템의 "동작 줄이기" 설정이면 주변 UI 애니메이션·강조 깜박임을 줄인다. **게임 캔버스의 폭발·연출은 원본대로 유지**하고 깜박임 강조(타이머 10초)는 색 변경으로 대체 |
| 터치 타깃 | 44px 이상 |
| 소리 | 모든 효과음은 끌 수 있다. 경고음 추가 없음(원본 구성 유지) |
| 글자 크기 | 주변 UI 글자 크기 3단계 조절 [제안] |

### U6.2 반응형
| 해상도 | 레이아웃 [제안] |
|---|---|
| 데스크톱(≥1024px) | 캔버스 중앙, 우측 플레이어 리스트, 하단 조작바 |
| 태블릿(600~1023px) | 캔버스 위, 조작 패널 아래, 플레이어 리스트는 접이식 |
| 모바일(<600px) | 세로: 캔버스+하단 시트(U3). 가로: 캔버스 중앙+좌우 조작 |
| 대기실/로비 | 목록·슬롯은 1열로 접힘, 채팅은 하단 시트 |

### U6.3 해상도 스케일링과 캔버스
- **논리 해상도는 서버가 고정한다**(방마다 다르면 안 됨). 사유: DOC는 중력 단위를 픽셀로 적었고 월드 폭이 화면 폭이다. 해상도를 바꾸면 사거리·벽 거리·지형 형태가 바뀌어 규칙이 달라질 수 있다. 원본 하드웨어 메뉴의 기본은 360x480이다.
- **확인 필요:** 360x480은 4:3 모니터에 표시되던 비정방(세로가 긴) 픽셀일 가능성이 있다. 표시 비율은 EXE·캡처로 확인한다. 선택지는 640x480(정방 4:3)과 360x480 + 비율 보정이며, 권고는 **원본 기본(360x480)과 원본 표시 비율 유지**다.
- 캔버스는 정수배 스케일을 우선하고, 남는 공간은 레터박스로 처리한다. CSS는 `image-rendering: pixelated` 계열로 픽셀 질감을 보존한다.
- 비정수배일 때도 가장자리 보간으로 번지지 않게 한다.
- HiDPI에서는 논리 해상도를 키우지 않고 확대만 한다(엔진 동일).

### U6.4 다크 톤·폰트
- 주변 UI는 다크 테마를 기본으로 한다. 팔레트는 게임 캔버스의 256색을 가리지 않는 저채도 배경(캔버스 주위 레터박스는 거의 검정) [제안].
- 주변 UI 폰트는 한국어 가독성이 높은 산세리프(예: 프리텐다드 계열) [제안, 라이선스 확인 필요]. 숫자는 고정폭 계열을 써서 파워·각도 숫자가 흔들리지 않게 한다.
- **캔버스 안 텍스트**(말풍선, 이름표, 폭발 점수 등)에 한글이 필요하다. 원본은 영문 비트맵 폰트이므로 한글 비트맵/픽셀 폰트를 쓰는 방안이 필요하다 [제안, 후보 선정과 라이선스는 확인 필요].
- **권고(A11 확정 제안):** HUD·메뉴·패널·상점은 HTML(현대 폰트)로 이전하고, 캔버스에는 게임 월드(지형, 탱크, 투사체, 폭발, 말풍선, 이름표)만 남긴다. 원본 상단바의 "텍스트 톤"은 HUD에서 재현하지 않는다(사용자 지시: UI 현대화).
