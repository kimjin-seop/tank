
# Scorched Earth v1.5 웹 온라인 재구현 요구사항 명세

작성: 문기획 / 근거: SCORCH.DOC(v1.5, 1995-06), README, TALK1.CFG, TALK2.CFG
표기 규칙: 수치는 DOC에 명시된 것만 기재한다. DOC에 없으면 **미상**으로 표기하고, 구현 단계에서 EXE 분석 또는 원본 실행 캡처로 보완한다. **[제안]**은 DOC에 없는 신규 설계 제안, **[확인 필요]**는 결정이나 검증이 필요한 항목이다.

## 0. 충실도 원칙 (사용자 확정)

### 0.3 충실도 검증 방법 [제안]
- 원본 SCORCH.EXE를 DOSBox 계열에서 실행해 기준 녹화본을 만든다. 같은 시드와 입력으로 탄도 궤적, 낙하 피해, 폭발 크기를 비교한다.
- 키 반복 속도, 발사 지연, 효과음 길이 등 DOC에 없는 값은 EXE 분석 또는 녹화본 프레임 분석으로 추출한다.
- 판정 기준: 각 항목이 "미상 해소" 상태가 되기 전에는 구현 값을 임시값으로 표시한다.
- **[확인 필요]** 원본 EXE의 분석·역공학이 사용자 승인 범위인지 확인한다. 지시문에 "EXE 분석으로 보완"이 있으므로 가정은 승인이다.
- **[확인 필요]** 법무 항목: 원본은 쉐어웨어이고 저작권이 있다(Copyright 1991-1995 Wendell Hicken). 타이틀명, 대사 텍스트, `.MTN` 산 이미지, 사운드 재사용 여부는 전문가 확인이 필요하다. 개발은 막지 않고 공개 전 메모로만 유지한다.

## 1. 게임 규칙 전체

### 1.1 기본 구성
- 플레이어 2~10명(기본 2), 컴퓨터 포함. 라운드 1~1000(기본 10).
- 탱크 에너지 100. 최대 파워 = 남은 에너지 × 10(에너지 100이면 1000). 에너지 0이면 사망.
- 탱크는 지형 위에 대체로 고르게 배치된다(배치 알고리즘 미상).
- 탱크 번호: 화면 왼쪽부터 1, 2, ...(10번째는 0 키). 사망하면 번호가 재배정된다.
- 바퀴·트레드가 없는 아이콘은 고정 포대로, 연료를 사거나 쓸 수 없고 낙하 외에는 움직이지 못한다.
- 라운드 종료는 한 명(또는 팀)만 생존했을 때다.

### 1.2 턴 흐름 (순차 모드, 기본)
1. 라운드 시작 시 지형·하늘·바람·벽 효과를 결정한다.
2. 순서에 따라 한 플레이어가 파워·각도·무기를 정하고 이동/방어 준비(탱크 제어 패널)를 거쳐 발사한다.
3. 발사 후 투사체가 이동하고, 폭발 처리와 피해, 지형 낙하, 탱크 낙하 순으로 진행한다([확인 필요]: 정확한 처리 순서).
4. 다음 플레이어로 넘어간다.
5. 한 명만 남으면 라운드를 종료하고 점수 정산 후 구매 화면으로 간다.

플레이 순서(Play Order, 기본 RANDOM)는 다음과 같다.
- RANDOM: 매 턴 순서를 무작위로 정한다.
- LOSERS-FIRST: 꼴찌가 먼저, 1등이 마지막에 쏜다.
- WINNERS-FIRST: 위와 반대.
- ROUND-ROBIN: 순서는 무작위이지만 라운드마다 첫 발사자가 다음 플레이어로 순환한다.

**모호점:** Quick Start에서는 "플레이어가 무작위로 선택되어 왼쪽에서 오른쪽으로 진행"이라고 한다. Play Order 표(기본 RANDOM, 매 턴 무작위)와 충돌하는 것으로 보인다. 기본은 Play Order 표를 우선하고, 순서 정의는 EXE로 확인한다.

### 1.3 각도·파워 조작
| 항목 | 규칙 |
|---|---|
| 파워 | 0 ~ 현재 최대(에너지×10). 최대 1000 |
| 각도 | 0 ~ 90(0=수평, 90=수직). 발사 방향은 탱크가 바라보는 쪽 |
| UP / DOWN | 파워 증가/감소(누르는 동안 지속) |
| PgUp / PgDn | 파워 고속 증감 |
| LEFT / RIGHT | 각도 CCW/CW 회전 |
| Shift + 방향키 | 저속 |
| Alt + 방향키 | 키 입력당 1 단위 |
| TAB / Shift-TAB | 무기 순방향/역방향 전환(소유한 무기만) |
| SPACE / ENTER | 발사 |
| 증감 속도(단위/초), 키 반복 | **미상** |

**미상·확인 필요:**
- 각도가 0~90이면 방향 전환은 어떻게 하는지, 즉 각도 이동이 탱크의 좌우 방향을 바꾸는지 EXE로 확인한다. DOC는 "탱크를 봐야 방향을 안다"라고만 한다.
- 키 반복 속도는 미상이다.

기타 입력은 다음과 같다.
- `t` 탱크 제어 패널, `i` 인벤토리, `k` 방해 금지 안내, `r` 후퇴, `u` 상태 갱신, `0~9` 탱크 정보.
- `r` 후퇴는 점수가 없고, 적의 득점을 막을 수 있다. 확인 후 헬기(G.N.A.T.)로 탈출하고 탱크는 폭발한다.
- 자살하면 현금이 감소한다. 감소량은 미상.
- 상태바(옵션) 단축키: `b` 배터리, `p` 파라슈트, `s` 방어구 선택, `e` 방어구 가동, `g` 유도, `f` 연료, `-` 컨택트 트리거.

### 1.4 연료·이동
- 연료탱크 1개당 연료 10 단위. 1픽셀 이동에 1 단위, 오르막은 경사에 따라 더 든다(공식 미상).
- 너무 가파른 언덕은 오를 수 없다. 내리막이 너무 가파르면 미끄러져 낙하하고 큰 피해를 입을 수 있으며 제어는 메인으로 복귀한다.
- 연료가 0이면 이동 불가. ESC로 이동을 마친다.
- 바퀴 없는 아이콘은 이동 불가.

### 1.5 낙하·낙하 피해
- Tanks Fall(기본 ON): 지반이 사라지면 탱크가 낙하한다.
- 낙하 피해량 공식은 **미상**(구현 단계에서 EXE로 보완).
- Impact Damage(기본 ON): ON이면 착지 때, OFF이면 낙하 중에 피해를 입는다. 총 피해량은 같다.
- 낙하 중 적 탱크 위에 착지하면 파라슈트도 피해를 막지 못한다.
- 파라슈트 규칙은 3.3 참고.

### 1.6 바람
- Max Wind 0~500(기본 200). 0이면 무풍("No Wind" 표시).
- Changing Wind(기본 OFF): ON이면 샷마다 약간 변한다.
- 표시는 방향 화살표와 숫자다. 바람 수치를 가속도로 환산하는 식은 **미상**.
- 라운드 시작 시 바람 결정 방식(분포)은 **미상**.

### 1.7 지형
| 항목 | 범위 | 기본 |
|---|---|---|
| Bumpiness | 0~100 | 20 |
| Slope | 0~100 | 20 |
| Flatten Peaks | ON/OFF | OFF |

- 지형 종류는 DOC상 "무작위 생성 지형"과 "스캔 산"이다. 이 외 지형 타입은 DOC에 없다.

### 1.15 시뮬레이티드(동시) 모드 / 동기(Synchronous) 모드
**Simultaneous**
- 모든 플레이어와 컴퓨터가 동시에 조준·발사. 키를 빨리 누르는 쪽이 자주 움직인다.
- 한 번 발사하면 그 투사체가 터질 때까지 다시 쏠 수 없으나, 비행 중에도 조준은 바꿀 수 있다.
- 6개 동작: 터렛 CW/CCW, 파워 +/-, 발사, 무기 전환.
- `i`, `t`, `r`, 마우스, 탱크 제어 패널이 없다. 방어구는 Auto Defense가 있을 때만 사용 가능. 연료·컨택트 트리거·유도는 쓸 수 없다.
- 파라슈트는 Auto Defense가 없으면 항상 deployed이고 임계값 변경 불가.
- 배터리 자동: 에너지가 91 미만이고 탱크가 살아 있으면 90을 넘을 때까지 필요한 만큼 배터리가 자동 사용된다.
- 상단바에 각 탱크의 파워와 무기가 탱크 색으로 표시된다. 파워 증가는 밝게, 감소는 어둡게, 무기 변경은 빨갛게, 배터리 자동 사용은 초록으로 깜박인다.
- 상태바 ON이면 각자의 남은 파워와 방어구도 표시된다.
- 라운드 종료는 순차 모드와 같고, 현금이 있으면 구매 화면을 거친다.
- 원본은 "3명 이하 권장"이다. 온라인 최대 인원 영향은 5.3 참고.

**Synchronous**
- 각 플레이어가 조준하고 "발사"하면 준비 상태(탱크 강조)가 되고, 전원이 준비되면 모든 샷이 동시에 발사된다. 살아남은 사람이 다시 다음 샷을 정한다.
- 모든 플레이어의 발사 수가 같으며, 마지막에 쏘는 쪽이 유리하다(정보 우위).
- 온라인에서는 다른 사람의 조준 정보를 노출하지 않는 것이 공정하다. 원본의 노출 범위는 **미상**이므로 [확인 필요].

### 3.2 방어구 상세 규칙
- 방어구는 에너지처럼 퍼센트로 표시된다(100% = 새것). 방어구 가동(`e`)은 현재 가동 중인 방어구를 제거하고 선택한 방어구를 100%로 올린다. 이때 제거된 방어구는 복구할 수 없다.
- 동일 종류의 가득 찬 방어구를 다시 가동하는 것은 불가하나, 종류를 바꾸는 것은 가능하다.
- "방어구 없음"을 선택하고 가동하면 방어구를 내린다.
- 방어구 내구 수치(HP), 데미지 흡수율, Mag Deflector의 힘, Force Shield 튕김 각, 방어구 failure 확률: 모두 **미상**.
- 레이저는 모든 방어구를 관통하나 Super Mag는 면역이다.
- 방어구를 직접 맞히면 폭발하지 않으므로, 방어구는 간접 공격(근접 폭발, napalm, 흙으로 덮은 뒤 컨택트 트리거, Sandhog)으로 무력화한다.

### 3.3 파라슈트 규칙
- 상태: passive / deployed. 기본 deployed, 안전 임계값 기본 5(1~100, 키보드로만 입력).
- 낙하 시 시스템이 예상 낙하 피해를 계산한다. deployed이고 임계값이 예상 피해 미만이면 파라슈트가 펼쳐지며 피해가 없다. passive이거나 예상 피해가 임계값 이하면 피해를 입는다.
- 파라슈트 1개가 낙하 1회에 소모되는지는 DOC에 명시가 없어 **확인 필요**(EXE로 검증).
- 파라슈트가 있어도 적 탱크 위에 착지하면 피해.

### 3.4 배터리
- 탱크 제어 패널로 사용하면 에너지 +10(상한 100 초과분은 100으로). 에너지가 100이면 사용 불가.
- 상태바에서 에너지가 가득 차지 않았을 때만 배터리 아이콘이 활성화된다.

### 3.5 트레이서(Tracer/Smoke Tracer)
- 2절 참고. Trace Paths가 ON이면 Smoke Tracer는 쓸모없는 아이템이 되어 Useless Items가 OFF일 때 상점에서 숨겨진다.

## 4. 라운드·경제

### 4.1 라운드 구조
1. (게임 시작) Cash at Start가 0이 아니면 첫 라운드 전 구매 화면.
2. 라운드 진행(1.2).
3. 라운드 종료 → 점수/현금 정산 → 구매 화면(현금이 있는 플레이어만) → 다음 라운드.
4. 설정된 라운드 수를 끝내면 종료. 최종 순위는 Scoring Mode에 따른다.
- 라운드 종료 후 상점은 플레이어가 한 명씩 순서대로 이용한다(순서 기준 미상). 각 플레이어의 상점 이용에는 상점 제한시간이 적용된다(5.7.2).
- 컴퓨터 구매는 Computers Buy ON일 때만.

### 4.2 이자
- 라운드를 시작할 때 은행에 쓰지 않은 현금이 있으면 이자를 받는다. Interest Rate 0~0.30, 기본 0.05(퍼센트 해석 5%).
- 복리 여부, 소수점 처리, 계산 시점(라운드 종료 vs 시작)의 정확한 규칙은 **미상**.
- 이자 수익은 상점의 "Update"에서 게임 시작 이후 누적을 확인한다.
- 이자율은 Auto Defense 가격에도 영향을 준다.

### 4.3 점수와 승리 보너스
| Scoring Mode | 설명 |
|---|---|
| BASIC | 탱크 처치와 라운드 생존에만 점수 |
| STANDARD(기본) | 처치 점수는 BASIC보다 적고, 탱크 또는 방어구를 피해 입힐 때마다 점수 |
| GREEDY | STANDARD와 같은 득점, 단 라운드 종료 후 순위는 순자산(은행 현금 + 보유 장비의 감가상각 가치) 기준 |

- 점수가 곧 돈이다("points mean money").
- 처치·생존·피해 점수의 구체적 금액, 승리 보너스 금액, 자살/팀킬 감점액, Mass Kill 분배 공식(남은 점수를 균등 분배)의 수치는 **미상**이다.
- 감가상각률(판매가)도 **미상**. 판매가는 수량에 따라 달라질 수 있고 라운드마다 갱신될 수 있다(DOC).

### 4.4 상점
- 두 분류: Weapons(총 아이콘), Miscellaneous(상자 아이콘). 이전/다음 페이지는 순환.
- 묶음 단위로 구매(묶음 수량은 2절·3절 표).
- 보유 한도 99. 초과 구매 시 할증은 2절 참고.
- 살 수 없는 아이템(자금 부족)은 목록에서 숨겨지고, 자금이 생기면 다시 표시된다.
- Baby Missile은 항상 99개(무제한).
- 판매: 인벤토리에서 아이템을 골라 수량을 선택하면 컴퓨터가 가격을 제시한다. 수락/거절. 가격은 수량에 따라 다르며 다음 라운드까지 바뀌지 않는다. Baby Missile은 팔 수 없다.
- Arms Level 초과 아이템은 사용 불가(표시되지 않는 것으로 해석 [확인 필요]).
- Useless Items OFF이면 효과 없는 아이템은 숨겨진다.
- Free Market ON: 많이 구매되는 품목은 가격 상승, 안 팔리는 품목은 하락한다. 가격은 흔들림이 있다. 원본은 scorch.mkt 파일로 게임 간 가격을 유지한다. 가격 변동 공식은 **미상**.
- Corporate 팀은 팀 은행 계좌 1개를 공유한다.
- 구매 화면에서 `Update`는 남은 라운드와 누적 이자를 표시한다.
- 상점 제한시간: 상점 이용에는 제한시간이 있고(60/90/120초, 기본 90초), 만료되면 서버가 자동으로 완료 처리한다(5.7.2).

## 5. 온라인 멀티플레이어 요구사항

DOC는 온라인을 다루지 않으므로 5절은 사용자 지시에 따른 요구사항이며, DOC에 근거가 없는 상세 값은 [제안]입니다. 로비·대기실은 "주변 UI"라 현대화 허용 범위입니다(0절). 방 코드/참가 코드 방식은 폐기합니다.

### 5.1 화면 흐름
1. **닉네임 입력** → 2. **방 목록** → (방 만들기 또는 방 선택) → 3. **대기실** → 4. **게임** → 종료 후 **대기실로 복귀**.
- 방 목록으로 돌아가는 "나가기"는 대기실에서 언제든 가능하다.
- 게임 중 이탈은 5.7절 재접속·이탈 규칙을 따른다.

### 5.2 접속과 닉네임
- 접속하면 닉네임을 입력한다. 가입/로그인은 없다(원본에도 계정 개념 없음).
- 닉네임 규칙 [제안]: 서버 전체에서 동시에 유일, 2~12자, 한글·영문·숫자, 금칙어 필터는 [확인 필요]. 중복이면 거절 안내.
- 접속 식별은 서버가 발급하는 세션 토큰으로 한다(재접속용, 5.8절).
- 원본에서 "이름"이 플레이어 이름이므로 닉네임이 게임 내 탱크 이름으로 쓰인다. 컴퓨터 플레이어는 닉네임과 겹치지 않는 이름을 자동 부여한다(DOC 규칙).

### 5.3 방 목록 화면
표시 항목(방 1개당):
| 항목 | 내용 |
|---|---|
| 방 제목 | 방장이 정한 제목 |
| 인원 | n/max (사람+컴퓨터 합계, 최대 2~10) |
| 모드 | 순차 / 동기 / 동시 |
| 상태 | 대기중 / 게임중 |
| 비밀번호 | 비밀번호방이면 잠금 표시 (선택 기능, 5.12 질문 참고) |

- 동작: 목록 자동 갱신(서버 푸시 또는 짧은 주기 폴링 [제안]), 방 선택 후 입장, 방 만들기 버튼.
- 인원이 가득 찬 방, 게임중 방은 입장 불가(버튼 비활성 또는 거절 메시지).
- 비밀번호방은 입장 시 비밀번호를 입력한다. 틀리면 거절(토스트).
- 정렬·검색·필터는 [제안] 1차 범위에서 제외(최근 생성 순).
- 빈 목록일 때 "방이 없습니다" 안내와 방 만들기 유도.
- 방 목록에서 보이는 모드·옵션 외 상세 옵션은 입장 후 대기실에서 본다.

### 5.4 방 만들기
입력:
- **방 제목** (필수) [제안: 1~30자].
- **최대 인원** 2~10 (원본 Players 범위).
- **게임 옵션 선택** (1.12절 전체 옵션: 진행 방식, 팀, 라운드 수, 시작 자금, 이자율, 점수 방식, 물리·지형·하늘·벽·무기 설정, 말하는 탱크 등. 0.2 변경 허용 항목 제외). 기본값은 1.12절 기본값. [제안] 화면은 "기본값으로 만들기"와 "옵션 열기"로 분리한다.
- **비밀번호** (선택) [제안: 4~12자, 평문 저장 금지·해시 보관].
생성 즉시 만든 사람이 **방장**이 되어 대기실로 이동한다.

### 5.5 대기실
화면 구성:
- **참가자 슬롯**: 최대 인원만큼 슬롯을 보여 준다. 슬롯에는 닉네임, 탱크 모양, 플레이어 색, 준비 상태, 방장 표시, (팀 모드일 때) 팀이 표시된다. 빈 슬롯은 "빈 자리"로 표시한다.
- **컴퓨터 슬롯**: 방장이 빈 슬롯에 컴퓨터를 추가/제거하고 성향 8종(모론~언노운)을 고른다 [제안, 이전 SPEC 유지]. 컴퓨터는 항상 준비 완료 상태다.
- **준비 토글**: 방장을 제외한 각자가 자기 준비를 켜고 끈다. 방장은 준비 개념이 없다.
- **시작 버튼**: 방장에게만 보인다. 활성 조건은 "방장 제외 사람 참가자 전원이 준비 완료이고, 사람+컴퓨터 합계 2명 이상"이다. 조건이 아니면 비활성이고, 비활성 이유를 툴팁이나 한 줄로 알린다.
- **방 설정:** 모든 참가자가 볼 수 있고 변경은 방장만 한다. 방 만들기(5.4)와 대기실 설정 모두에 **턴 제한시간**이 들어간다.
- 턴 제한시간 선택값은 30 / 45 / 60 / 90초이고, **기본은 60초** [제안]. **무제한은 선택할 수 없다** [제안, 6.4 질문 3]. 무제한을 허용하면 "제한시간 안에 발사하지 않으면 자동 패스"라는 확정 규칙이 무력화되기 때문이다.
- **강퇴**: 방장이 다른 참가자(사람)를 내보낸다. 강퇴된 사람은 방 목록으로 돌아가고 안내(토스트)를 받는다. 같은 방 재입장은 그 방이 존재하는 동안 차단한다 [제안].
- **방장 위임**: 방장이 나가면 자동으로 다른 사람에게 방장이 넘어간다. 대상은 방에 가장 오래 있던 사람(사람 참가자 우선) [제안]. 방장이 임의로 특정인에게 넘기는 수동 위임은 [제안, 5.12 질문].
- **대기실 채팅**: 참가자 전원이 텍스트 채팅을 한다. 닉네임과 메시지 표시, 길이 제한(예: 200자), 연속 전송 제한 [제안]. 시스템 메시지(입장/퇴장/준비/강퇴/방장 변경)도 같은 창에 표시한다.
- **탱크 모양·팀 선택**: 각자 자기 탱크 모양을 고른다(원본 아이콘 종류 유지, 바퀴 없는 고정 포대 포함). 팀 모드일 때 팀은 각자 선택하고 방장이 바꿀 수도 있다 [제안]. 플레이어 색은 슬롯에 따라 서버가 자동 배정한다(원본 규칙: 플레이어별 색 고정, 사용자 변경 불가).
- 방 옵션이 바뀌면 모든 참가자의 준비가 해제된다(기존 규칙 유지). 게임 중에는 변경할 수 없다.
- 팀 모드를 켰는데 팀 편성이 성립하지 않으면(예: 모든 사람이 같은 팀에 컴퓨터 없음) 시작할 수 없다. 팀 수·편성 규칙이 DOC에 없어 [확인 필요].

### 5.6 게임 시작·진행·종료
- **시작은 방장이 시작 버튼을 눌러야만** 한다. 전원 준비 완료여도 자동 시작하지 않는다.
- 시작하면 방 상태가 "게임중"으로 바뀌고 방 목록에 표시된다. 시작 시점의 참가자와 옵션이 확정된다.
- **게임 중 입장 불가**. 방 목록에서 입장이 막힌다.
- **관전은 가정으로 1차 범위 제외**: 게임중 방에는 들어갈 수 없고 관전 기능도 없다. 후속 옵션으로 "관전 허용"을 둘 수 있으나 5.12 질문에서 결정한다.
- 게임 진행은 5.7절(서버 권위)과 1절 규칙을 따른다. 원본의 라운드 구매 화면, 점수 정산은 그대로 진행한다.
- **게임 종료**(설정 라운드 수 완료, 또는 모두 이탈): 최종 순위 화면을 보여 준 뒤 전원 **대기실로 복귀**한다. 복귀 시 준비 상태는 모두 해제하고, 방 옵션과 방장은 유지하며, 방 상태는 "대기중"으로 돌아간다.
- 게임 중 방장이 이탈하면 방장이 위임되고 게임은 계속된다. 시작·옵션 변경 권한은 새 방장이 갖는다.
- 게임 중 강퇴·옵션 변경은 불가하다(대기실에서만).
- 시스템 메뉴 기능 중 "새 게임", "일괄 전멸"은 방장 권한으로 둔다(0.2 A4 대체) [확인 필요: 도입 여부].

### 5.7 서버 권위 시뮬레이션 (기존 5.2 유지)
- 모든 게임 상태 변화(물리, 폭발, 지형 변형, 피해, 경제, 점수, 바람, 난수)는 서버가 단독으로 계산한다. 클라이언트는 입력(각도/파워/무기/발사/장비 조작)만 보낸다.
- 서버는 입력을 검증한다(현재 턴 여부, 소유 아이템, 파워 상한, 연료 등). 클라이언트가 보낸 결과값은 신뢰하지 않는다.
- 시뮬레이션은 결정론적이어야 한다(같은 시드와 입력이면 같은 결과). 원본의 수치 표현(정수/고정소수)은 EXE 분석으로 확인한다 [확인 필요].
- 서버는 이벤트(투사체 경로, 폭발, 지형 델타, 낙하, 피해)를 스트림으로 보내고, 클라이언트는 원본 타이밍(0절)으로 재생한다. 판정은 서버가 확정한다.
- 난수는 서버 시드 기반이며 클라이언트에 미리 노출하지 않는다.

모드별 요구는 다음과 같다(기존 5.3 유지).
- **순차:** 서버가 턴을 관리한다. 방 옵션의 턴 제한시간이 적용되며, 제한시간 안에 발사하지 않으면 자동으로 턴이 넘어간다(5.7.1).
- **동시:** 각자 자기 클라이언트에서 입력하고 서버가 입력을 일정 주기로 반영한다. 반영 주기(키 반복 속도 재현)는 미상. **턴 제한시간은 적용하지 않는다**(가정). 동시 모드에는 "턴"이 없고 누구나 항상 조준·발사할 수 있기 때문이다. 이탈·방치는 5.8절 규칙으로만 처리한다. 동시 모드에 라운드 전체 제한을 둘지는 6.4 질문 4.
- **동기:** 조준 단계에 턴 제한시간이 적용된다(5.7.1). 대기 중 타인의 조준 값은 노출하지 않는다 [제안].
- 컴퓨터 플레이어는 서버가 구동한다. 컴퓨터는 타이머와 무관하게 서버가 정한 속도로 즉시 행동한다.

### 5.7.1 턴 제한시간 (사용자 확정, 신규)
**적용 범위**
| 모드 | 적용 |
|---|---|
| 순차 | 모든 턴에 적용(현재 턴 플레이어 한 명) |
| 동기 | 조준 단계에 적용(전원 공통 타이머 1개) |
| 동시 | 적용 안 함(가정) |

**규칙**
1. **시작:** 서버가 "턴 시작"을 확정한 시각부터 시작한다. 직전 샷의 이벤트 재생, 폭발, 지형·탱크 낙하, 정산이 끝난 뒤에 시작한다. 클라이언트가 연출을 재생하는 동안에는 시간이 가지 않도록, 서버가 이벤트별 재생 길이(원본 타이밍 기준)를 더해 시작 시각을 정한다 [확인 필요: 재생 길이는 EXE 분석 의존].
2. **진행:** 현재 턴 플레이어가 조준 중이든, 이동 제어판에서 이동 중이든, 탱크 제어판·인벤토리·표적 선택 창을 열어 두었든 **타이머는 계속 간다.** 일시정지는 없다.
3. **정지:** 발사가 확정된 순간 정지한다. 표적 선택(유도 장치)이나 배터리 수 선택(플라즈마 블라스트·레이저)처럼 발사 후 추가 입력이 필요한 무기는 그 입력까지 끝나 발사가 확정된 순간을 "발사 순간"으로 본다. 그 확정까지 타이머는 계속 간다.
4. **초과:** 제한시간이 끝나면 서버가 그 턴을 자동으로 넘긴다. **그 턴에는 발사가 없다.** 무기·유도·트리거·방어 장비는 발사 전에는 소모되지 않으므로 소모품은 줄지 않는다(DOC: "발사 전에는 사용되지 않는다"). 이미 쓴 연료·배터리·실드 가동은 되돌리지 않는다.
5. **마감 판정은 서버 수신 시각 기준이다.** 마감 이후에 도착한 발사 입력은 거부한다. 네트워크 지연 보정용 유예(예: 0.25초)를 둘지는 [제안: 두지 않음, 구현 후 조정].
6. **조준 상태:** 시간 초과로 넘어가도 해당 플레이어의 마지막 각도·파워·선택 무기는 유지한다 [제안, 확인 필요: 원본은 다음 턴에도 이전 값이 유지되는지 DOC에 명시 없음].
7. **동기 모드:** 조준 단계 타이머가 끝나면, 아직 준비(발사 확정)하지 않은 플레이어는 이번 샷에 발사하지 않고, 준비한 플레이어의 샷만 동시에 발사된다. 전원이 준비하면 타이머 만료 전에도 즉시 발사된다. 전원이 미준비로 끝나면 샷 없이 다음 조준 단계로 넘어간다.
8. **서버 단독 관리:** 타이머는 서버가 단독으로 관리한다(서버 단조 시계 기준). 클라이언트 시계는 신뢰하지 않는다. 서버는 "턴 마감 시각"과 서버 시각을 클라이언트에 보내고, 클라이언트는 그것으로 카운트다운을 **표시만** 한다. 클라이언트가 시간을 조작하거나 늦게 보내도 판정에 영향이 없다.
9. **표시(HUD):**
   - 남은 시간을 초 단위 카운트다운 숫자와 진행 바로 보여 준다. 현재 턴 플레이어뿐 아니라 방 전원이 본다.
   - 남은 10초 이하에서 강조한다(색 변경과 깜박임 [제안]). 원본 효과음 구성을 바꾸지 않기 위해 경고음은 넣지 않는다 [제안].
   - 타이머 위젯은 원본 상단바 바깥의 별도 영역에 둔다 [제안]. 게임 화면 안의 원본 시각 톤을 훼손하지 않기 위해서다.
10. **시간 초과 알림:** 시간 초과로 턴이 넘어가면 방 전원에게 토스트를 띄운다(예: "시간 초과! ○○님의 턴이 넘어갑니다"). 인라인 박스는 쓰지 않는다.
11. **방치 처리(연속 초과):** 같은 플레이어가 **연속 3회** 시간 초과를 하면 [제안, 6.4 질문 3] 다음과 같이 처리한다. 연속 횟수는 그 플레이어가 유효한 발사를 한 번 하면 0으로 돌아간다.
    - 접속 중인 플레이어(방치): 탱크를 **후퇴** 처리한다(원본 후퇴 규칙 재사용: 점수 없음, 탱크 폭발, 비상 헬기 연출).
    - 접속이 끊긴 플레이어: **컴퓨터 대행**으로 전환한다. 재접속하면 즉시 제어를 회수한다. 대행 AI 성향은 모론 [제안, 확인 필요].
12. 서버가 타이머와 판정에 쓰는 모든 값은 서버에 저장하며 클라이언트에 맡기지 않는다.

### 5.7.2 상점 제한시간 (사용자 확정, 신규)
라운드 사이 무기 구매 화면(상점)에도 제한시간을 둔다. 원본에는 없는 규칙이다(A15).

**규칙**
1. **적용 대상:** 라운드 종료 정산 후 구매 단계에서 각 플레이어는 자기 상점 시간에 제한시간이 적용된다. 상점은 원본 순서대로 한 명씩 순차 진행하며, 그 순서는 유지한다(4.1).
2. **시작:** 서버가 해당 플레이어의 상점 화면 진입을 확정한 시각부터 시작한다.
3. **진행:** 구매·판매·인벤토리·현황 조작 중에도 타이머는 계속 간다. 일시정지는 없다.
4. **만료:** 시간이 끝나면 서버가 그 플레이어의 상점을 자동으로 "완료" 처리한다. 이미 확정된 구매·판매는 유지한다. 진행 중이던 판매 제시가(수락 전)는 거절 처리한다.
5. **서버 단독 시계:** 타이머는 서버가 단독으로 관리하며 클라이언트 시계는 신뢰하지 않는다. 서버가 보낸 마감 시각으로 클라이언트는 카운트다운을 표시만 한다.
6. **표시(HUD):** 상점 헤더에 남은 시간 카운트다운과 진행 바를 보여 주고, 남은 10초 이하에서 강조한다.
7. **시간 초과 알림:** 만료 시 토스트를 띄운다(예: "상점 시간 초과! ○○님의 구매가 종료됩니다"). 인라인 박스는 쓰지 않는다.
8. **컴퓨터 플레이어:** 서버가 즉시 구매하므로 타이머를 적용하지 않는다.
9. **접속 끊김:** 접속이 끊긴 플레이어도 같은 타이머로 진행되어, 만료되면 자동 완료된다.
10. **건너뜀:** 구매할 현금이 없는 플레이어는 상점을 건너뛴다(원본: 현금이 있는 플레이어만 상점 이용, 4.1).
11. **대기 중 표시:** 다른 플레이어에게는 대기 중에 "구매 중: ○○ n초"를 표시한다.
12. **설정:** 60 / 90 / 120초 중 선택, 기본 90초. 무제한은 선택할 수 없다(1.12, 6.4 3-e).

### 5.8 재접속·이탈
- **대기실에서 연결이 끊김:** 일정 유예(예: 30초) 후 슬롯을 해제한다 [제안]. 유예 안에 같은 세션 토큰으로 돌아오면 같은 슬롯으로 복귀한다.
- **게임 중 끊김:** 서버는 탱크를 유지하고 **같은 턴 타이머를 그대로 적용한다.** 현재 턴 플레이어가 끊겼다면 타이머가 만료될 때 자동 패스된다(타이머를 멈추거나 단축하지 않는다). 유예(30초 [제안]) 안에 세션 토큰으로 돌아오면 같은 좌석으로 복귀하고 현재 상태 스냅샷(지형, 탱크, 인벤토리, 바람, 점수, 현재 단계와 남은 시간)을 받는다. 게임중 방은 입장이 막혀 있으므로 재접속만 허용한다.
- **유예 초과 또는 연속 시간 초과:** 5.7.1의 11번 규칙에 따라 컴퓨터 대행으로 전환한다. 유예가 지났어도 연속 초과 횟수가 3회 미만이면 그때까지는 매 턴 타이머 만료로 자동 패스한다(즉시 대행으로 바꾸지 않는다) [제안].
- **방장이 끊김:** 유예 초과 시 방장이 위임된다.
- **방에 사람 참가자가 0명:** 방을 삭제하고 목록에서 제거한다. 컴퓨터만 남은 방은 유지하지 않는다.

### 5.9 방 목록과 상태 동기화
- 방 생성, 삭제, 인원 변화, 대기중/게임중 전환은 방 목록에 즉시 반영한다.
- 동시에 여러 사람이 같은 마지막 빈 자리에 입장하면 서버가 먼저 도착한 요청만 받아들이고 나머지는 "방이 가득 찼습니다"로 거절한다.
- 서버 재시작 시 방과 게임 상태의 복구 여부는 [확인 필요](1차는 복구하지 않고 모두 방 목록으로 돌아간다).
- 서버는 현재 턴의 마감 시각과 남은 시간, 연속 초과 횟수를 상태 스냅샷과 재접속 응답에 포함한다.

### 5.10 기타
- 채팅: 대기실 채팅만 요구한다. 게임 중 채팅은 DOC에 없고 [확인 필요]. 말하는 탱크(AI 대사)는 원본 규칙을 그대로 유지한다(8.8절).
- 치팅 방지: 서버 권위로 충족. 입력·채팅 전송에 레이트 제한 필요.
- 영속성: 계정, 전적은 없다. 자유 시장 가격 상태(원본 scorch.mkt)를 방 단위로 둘지 서버 전역으로 둘지 [확인 필요]. 기본 가정은 방 단위, 게임이 끝나면 폐기.
- 동시 접속 규모·지연 목표는 [확인 필요].
- 모든 오류·거절 사유(닉네임 중복, 가득 참, 비밀번호 오류, 강퇴 등)는 인라인 박스가 아니라 토스트로 알린다.
- 로비 설명 문구는 최소화한다(안내는 꼭 필요한 한 줄).

| AC-L8 | 방장이 아닌 참가자가 준비를 켜고 끄면 모든 참가자 화면에 즉시 반영된다 |

| AC-L11 | 방장만 방 설정을 바꿀 수 있고, 바꾸면 모든 참가자의 준비가 해제되며 변경된 옵션이 전원에게 보인다 |

| AC-L13 | 방장이 나가거나 연결이 끊겨 유예가 지나면 다음 사람에게 방장이 위임되고, 새 방장에게 시작 버튼과 설정 권한이 생긴다. 시스템 메시지로 알린다 |

## 6. 모호점·가정

### 6.1 가정
1. "원본 그대로"는 DOC에 기술된 게임 규칙·옵션·수치와 EXE에서 확인되는 동작을 뜻한다.
2. DOC의 "미상" 항목은 구현 단계에서 EXE 분석(역공학) 또는 원본 실행 캡처로 채운다.
3. 0.2 변경 허용 목록의 항목만 원본과 달라질 수 있다.
4. 온라인 항목은 DOC 외 신규 설계이며, 게임 규칙 자체는 바꾸지 않는다.
5. 법무 사항(저작권, 상표, 에셋 재사용)은 개발을 막지 않고 공개 전 메모로만 유지한다.
6. 동시 모드에는 턴 제한시간을 적용하지 않는다. 턴 개념이 없고, 키 입력은 항상 열려 있기 때문이다.
